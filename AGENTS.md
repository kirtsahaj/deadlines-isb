- Derive deadline term/course filters at runtime from Moodle short names so existing rows need no migration.
- Keep phone installability manifest-only; offline caching is intentionally excluded to protect fresh authenticated data. Instead, src/lib/queryPersist saves the signed-in user's screen data (allowlisted query keys) to localStorage, restores it on open for an instant first paint and refreshes in the background; per-user, max 24h, cleared on sign-out. Queries default to staleTime 2 min / gcTime 24h. A remembered school-account check (account-access-ok-v1) lets later opens skip the "Loading…" gate.
- eLearn launch URLs are generated on interaction in a shared browser-safe helper so every attempt gets a fresh passport.
- Detect phone browsers after hydration and keep Chrome-opening URL schemes in a shared browser-safe helper; browser handoffs are explicit and public setup URL copying has a manual fallback.
- Clipboard connection goes through a browser-safe helper that validates before sending only the REST token; permission failures return a manual-paste outcome without attempting a connection.
- Managed scheduled routes authenticate with the generated cron helper; dispatch one bounded account sync per same-origin invocation and retain it through the Worker request waitUntil hook so scheduler timeouts do not interrupt work.
- The shared sync policy gates snapshot removal and fresh-data success; both initial and background sync use the same read-only pipeline to preserve deadline semantics.
- Background refresh runs on a 15-minute tick; each account gets a stable hash-derived slot in a 2-hour cycle so load spreads evenly as users grow, and dispatch is throttled to pairs to stay polite to eLearn.
- Deadline reminders use self-contained WebCrypto Web Push (src/lib/push) driven by a managed 15-minute schedule, deduped per deadline+due time; no Node push libraries because the server runs on Workers.
- The admin dashboard is limited to one hardcoded email, checked server-side through the verified sign-in email, because the owner asked that only they have access.
- Term 5 catalog and class list ship as server-only JSON (src/lib/term5/data, imported only from *.server.ts) because the roster holds personal data and the catalog is a fixed snapshot; only per-user corrections and the shared pool live in the database. Each campus (MOH, HYD) has its own catalog/roster pair regenerated by scripts/import_hyderabad_term5.py-style converters; campus comes from the roster, eLearn matching uses the PGP<campus> short name and the shared pool keys non-Mohali courses as <campus>.<code> so same-code offerings never mix.
- Deadline merging, confidence and reminder eligibility live in one pure browser-safe module (src/lib/term5/model.ts) used by both the Deadlines screen and the reminder job so what students see and what they're notified about never diverge.
- The shared section pool stores course-level deadline metadata keyed by course, eLearn activity key and contributor section with no user identifiers; it is server-access only and used only for students without their own successful sync.
- Navigation: no top bar; pages start with their heading, padded with env(safe-area-inset-*) for notches. A plain full-width bottom bar in the card colour with a top border (48px buttons; bottom padding = max(0.75rem, safe-area-inset-bottom + 6px) for home bars/gesture pills) holds content-width text tabs (see Navigation tabs rule) plus a narrow Menu icon; the current tab is a soft primary tint with primary text; prereads appear only on the Prereads page, while reminders still cover them.
- Schedule mapping and preread projection share the browser-safe preparation module for UI and reminders; bundle readings at the first applicable class so shared readings never generate repeated tasks.
- eLearn destinations use validated numeric IDs and Moodle instance parameters, with course fallback; never treat instance IDs as module IDs or include credentials in URLs.
- Assessment matching uses normalized entities, curated company aliases, meaningful tokens and unambiguous course/date/scope candidates; no AI calls are required.
- Discovery-inside-window alerts and scheduled reminders use the same merged identities and atomic reminder claim helper to prevent duplicate outline/eLearn reminders.
- A root ThemeProvider applies explicit day/night preferences after hydration; theme storage is browser-only and defaults to light to keep SSR deterministic.
- Tile accents use semantic global tokens keyed by presentation type; Schedule shares the preread role without changing academic or confidence logic.
- Placements intake: Resend `email.received` webhook at /api/public/resend-inbound verifies the Svix signature over raw bytes, then fetches the message and raw MIME from Resend with a server-only key; the pure pipeline (src/lib/jobs) checks recipient, owner forwarder and receiver-computed auth, finds the cas@isb.edu original (attached .eml, bounded nesting, or inline), reads real "Job Details Modified" mails from the CAS Field/Previous/Present table, records each original once in an "applying" state with a lease so failed or concurrent deliveries resume instead of being lost, and merges only explicitly stated fields via a JobStore interface so the logic is testable in memory. Source mail metadata stays in service-only tables; students get sanitized facts via server functions.
- Navigation tabs: Assignments and Placements for every school account; Classes is added (second, between Assignments and Placements) only for roster students.
- Job reminders (12h and 3h, explicit times only) run on their own managed schedule (/api/public/placement-reminders), fully separate from academic reminders, claimed atomically per user/job/due time/offset.
- Typography: one self-hosted variable font (Geist, public/fonts, preloaded) for body and headings; no Google Fonts request. Font sizes and weights were left as they were when switching from Plus Jakarta Sans.
- Colour scheme: quiet neutral base with white cards and near-black ink; one purple primary for selected/active things; gradient title (.title-gradient) only on "Hello <name>!" on Assignments (Classes and Placements titles stay plain). Page background lives on a fixed body::before layer (iPhone ignores background-attachment: fixed): light mode near-white at the top → faint pink at the bottom, dark mode near-black at the top → deep purple-pink at the bottom; the top colour equals --background and the theme-color (ThemeProvider CHROME) so the status bar blends, the sheen sits on body::after masked out of the top 160px, and the frosted bar tint (--nav-frost) is the bottom colour so the page fades into it (tokens --page-gradient, --page-glow, --page-sheen); page wrappers must not paint bg-background over it. Bottom bar is frosted glass (.nav-frost: tinted, backdrop blur). States: --soon coral, --urgent raspberry (last 12h, Past due, bell off), source marks: a small outline icon in a thin circle on each Assignments tile (own eLearn = person, classmates/section = two people, outline or estimate = document), one muted grey for everyone, raspberry (--urgent, outline only) once we know eLearn isn't connected (never while loading); tap for the source popup, which names the source in plain words ("From your eLearn" etc., never "confidence") and, when not connected, shows a red-tinted "eLearn not connected" box with the purple Connect eLearn button; light-mode fills are toned down from full saturation by choice. Green stays for Done/Submitted; red (--destructive) only for destructive actions and errors.
- Three section bells (AlertsBell): Assignments → user_settings.deadline_reminders (3h reminders + new-deadline alerts, incl. classmates'), Classes → class_reminders (preread reminders), Placements → job_reminders. All account-wide, default true; enabling device push (any bell or Menu) always sets all three true. Off state = solid red circle with white BellOff, on = grey Bell on the muted toggle-track grey. The toolbar line stays neutral and flat: search bar, sort button and on-state bell share the muted toggle-track grey with no border or shadow (search turns white with a thin border while focused); grey icons, normal text; purple was tried and rejected as too much. Only the selected toggle is purple. Classes: today reads "Today · 28 Oct" (no weekday so it fits at 360px). Tapping an off bell on iPhone Safari opens Add to Home Screen steps (push needs the installed app); on Android the "alerts on" toast offers Install app via the beforeinstallprompt event captured in src/lib/installEvent.ts (imported from the root).
- Bell on = grey icon on the same muted grey as the Upcoming/Past track (no border, no shadow) so it blends in; off = solid red circle with a white BellOff. Turning notifications off (any bell, or Menu "Turn off on this device") always asks first via ConfirmTurnOff: "Turn off" red outline left, "Keep on" solid green right; turning on never asks. The setup banner no longer carries a notifications nudge (bells and Menu cover it); it keeps eLearn connect and home screen. Bell shows its last known device state (localStorage alerts-device-on-v1) and a plain grey bell while unknown, so tab switches never flash red. Red only after the check confirms off.
- Soon pills (src/lib/soon.ts): Assignments and timed jobs show "Due/Closes in Xh" within 24h and "Due/Closes tomorrow" when more than 24h away but dated tomorrow (IST), and "Due/Closes soon" for anything else within 48h (tone "later": a slightly yellower golden-peach than the coral "soon"); red within 12h, amber before. Date-only jobs: "Closes tomorrow" amber, "Closes today" red. Classes "Starts in Xh" within 6h (red last 30m), "On now" (primary tint). New tags on Assignments and Placements only (not Classes, by choice).
- The shared section pool retires rows only after a complete contributor sync: rows in a course+section that sync covers but did not reconfirm are set inactive; a later sighting reactivates them.
- Placements intake health: job_inbound_messages is the log (webhook failures before the pipeline leave a status=received row with reason error:<code>). Pure helpers in src/lib/jobs/intake.ts define buckets, problems and the "forwarded" heartbeat; Admin shows an intake card; the placement-reminders schedule pushes owner-only alerts (24h silence, rejected/failed emails) deduped via claimReminder; Placements shows "Live" while a forwarded email arrived within 48h.
- Assignments ticks: deadline_done(user_id, item_key) with RLS; keys from model.doneKeys (elearn:<activity key> shared across classmates, outline:<occurrence>). The type tag always stays on the left; the right shows an empty tick, a soft green "✓ Done" pill (student's tick, tap to undo) or a solid green "✓ Submitted" pill (eLearn, locked). Finished tiles fade except that control; undated done items move to Past; done items get no Past due and no reminders.
- Assignment tiles show the soon pill above and a NEW tag for items absent at the previous visit on this device (localStorage); Placements tiles show NEW the same way.
- Link previews: public/og-image-v2.jpg (1200x630, dark design, ~85KB) referenced by og:image/twitter:image in the root head; bump the filename when it changes so WhatsApp refetches.
- Each main tab (Assignments, Classes, Placements) has a ShareButton alone in the top-right (muted grey circle like the bell): native share sheet with the single SHARE_MESSAGE (components/ShareButton) + the app URL, or copy-to-clipboard with a "Link copied" toast. Assignments refresh is an uncoloured ↻ icon at the start of the "Assignments synced X ago" line (spins while refreshing, labelled "Refresh now" for screen readers) (only when eLearn is connected).
- Menu opens with a "Share the app" tile (surface-card, purple icon circle, chevron) above Display; same SHARE_MESSAGE, with Copy link / WhatsApp fallback when there is no share sheet.
